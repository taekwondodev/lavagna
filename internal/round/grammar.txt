# Per-question round grammar

A call contains one or more questions. A level-1 title starts each question and
requires an id; `after` is optional and names question ids in the phase.

```markdown
# What should happen after a crash? {id="crash" after="storage"}
A concise lead for this question.

## Capire
Explain the current behavior and problem.

::: excerpt internal/store/store.go:40-46 45!1
`os.WriteFile` truncates before writing.
:::

## Confrontare
Compare alternatives and consequences.

## Decidere
- [atomic] Write a temporary file, then rename {recommended}
  The file is always old or new; one fsync per save.
  => The old file remains intact until rename.
- [journal] Append records and recover the last valid record

A final paragraph may explain the recommendation.

# What should be retained? {id="retention"}
```

The second title above is a planned question: it has no body or artifact yet.
A later call can supply its complete question with the same id. A complete
question replaces its previous version together with its resources.

## Titles, ids and dependencies

- Question ids match `[a-z0-9][a-z0-9_-]{0,39}` and are unique in a phase.
- A title is one line, at most 120 characters.
- `after="id other-id"` names known questions; dependencies must not cycle.
- `now` is reserved for the present state of diagrams.

## Chapters and choices

- `## Capire`, `## Confrontare`, `## Decidere` are optional except Decidere for
  a complete question; use that order. `###` headings are content headings.
- A complete question has 2 to 6 options, each written `- [id] label`.
  Option ids use the question id pattern; `now` is reserved.
- At most one option ends in `{recommended}`.
- An indented `=> consequence` line gives that option's effect; at most one per
  option. Other indented lines describe the option. A paragraph after the
  options gives the reason for the recommendation. A free-text answer is
  always available and needs no syntax.
- The page shows the title, the lead (text before the first chapter) and
  Decidere as 03 in its own controls, as plain text with `code` and **bold**.
  Capire and Confrontare render as 01 and 02 in the question's frame; an empty
  chapter is hidden. 02 starts with an Anteprima chip per option and the effect
  line of the variant shown: the preview, else the choice, else the
  recommended option.
- A bare title is planned and has no question artifact.
- A raw HTML block renders inside `.raw > .raw-stage`. A block wider than the
  column is fitted, with Expand below 85 %; give screens their native width.
- `::: excerpt path:start-end 45!1` includes a source excerpt; `45!1` marks
  line 45 as a problem with badge 1. Separate marks with spaces.
- `{ref}`, `data-ref`, level-1 chapter headings, and shared/root resources are
  unsupported. Anchors are not part of per-question feedback.

## Resources and bounds

For `DIR/round.md`, question `crash` owns files only under `DIR/crash/`. A
question's frame is served at `/f/<key>/<question-id>/`; references name files
as `<question-id>/file`. Only that question's `.js` and `.css` run in its frame.
No resources are shared across questions.

Scripts follow the choice without asking for it. The frame's `<html>` carries
`data-option` (the selected option id, absent when none), `data-free` (`true`
when a free-text answer exists) and `data-variant` (the option 02 shows), and
`document` receives a `lavagna:option` event with `detail: {option, free,
variant}` on load and on every change. The frame never receives the free text
or any message.

Input text, resources and rendered excerpts are bounded to 4 MiB and at most
32 files per call. Retained question artifacts are bounded to 6 MiB. Resource
paths must be regular files below the question directory; symlinks are refused.

## Calls after the first

Lavagna keeps every question of the phase in its ledger, so a later call sends
only what changes. Call elements stand outside questions, start at the line
beginning and close with `:::`:

```markdown
::: phase Session archive
:::
::: settled storage
No new dependency.
:::
::: settled retention week
The weekend is covered.
:::
::: reply crash
Rename is atomic on one file system.
:::
::: reply
A message for the Overview.
:::
```

- `::: phase TITLE` names the phase; only in the first call of a phase.
- `::: settled ID` closes a question with the user's recorded answer;
  `::: settled ID OPTION` closes it with that option of the current version.
  The body is the Why of its decisions row. Settling needs a recorded answer
  or an option, and may repeat in a later call to change the decision.
- A whole question with a known id replaces it in its round. The recorded
  choice survives when its option id survives; a free-text answer always does.
  Replacing a settled question reopens it in the current round.
- `::: reply ID` posts a message in that question's discussion, closed rounds
  included; `::: reply` posts to the Overview. One message is at most 32 KiB.
- A new question with a body opens the next round, and every unsettled
  question of the current round moves into it. Replies, settles and
  replacements stay in the current round.
- `::: recap` with no body, inside a question, renders the decisions table
  (question, decision, round, why, rejected options) after this call's settles.
- A call with no element only resumes waiting, for example after Esc.

Elements apply in the order phase, settled, replacements, reply, new
questions; a reply cannot address a question new in the same call. Any
invalid element rejects the whole call. The current versions of all questions
must fit 16 MiB, rendered with their resources. After close, the one-day expiry or an upgrade the
phase starts empty: `reply` or `settled` on an unknown id is invalid, and the
agent sends complete questions again.

## Feedback

One Send returns `questions`, keyed by id, and optional `overview`. Each batch
repeats the answers of the current round's open questions; questions of closed
rounds carry only messages and images. A question may
have `choice` or `answer` (never both), `messages`, and `images`; empty fields
are omitted. Above 2 KiB the outcome is deferred: choices remain visible,
messages and images become counts, and a free-text answer is `true`. Read full
feedback with `lavagna feedback SUBMISSION --question ID`, `--overview`, or
`--all`. The selectors are mutually exclusive. The default reprints the
summary. Unknown ids and questions without feedback in the selected batch are
errors.

A batch admits at most 32 KiB of text including answers, a 48 KiB record, and
8 screenshots of up to 10 MiB each. `close` and the one-day sweep remove
question artifacts and feedback.
